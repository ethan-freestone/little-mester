# Phase 1 B0 smoke / hosted-CI / parent overlap dispositions

This inventory was reconstructed from the current source after A1 acceptance.
No separately persisted smoke-versus-CI inventory was found. The 2026-11-15
Sol note on #55 is the B1 shared-guest design, not a prior B0 inventory.

| Behavior | Current implementations and existing reuse | Disposition |
| --- | --- | --- |
| Guest assets and directory contracts | `lib/vm/parent-session-contract.py` supplies canonical protected parent launch assets; hosted CI checks equivalent installed guest assets in `tests/ci-kvm-capability.sh`; smoke cloud-init is generated by `lib/vm/host-launcher.sh`. | **Consolidate where exact asset semantics match** (already done for parent launch assets); keep smoke and CI provisioning contracts separate because their cloud-init and guest workload policies differ. |
| Disposable image, overlay and QEMU launch | Smoke provisions/downloads and converts its pinned image in `host-launcher.sh`; CI builds disposable inputs and uses `tests/ci-kvm-contract.sh`; parent disk provisioning and launch are in `parent-provision.py` / `parent-supervisor.py`. | **Intentionally separate.** Disposable overlay, owner smoke run directory, and persistent-parent disk have different ownership, durability, and failure policies. No shared generic VM launcher. |
| QEMU identity, signaling and reaping | Smoke uses `host-launcher.sh` identity records and pidfd stop/reap; CI uses `ci-process-signal.py` through `ci-kvm-qemu-stop.sh`; parent owns its supervisor and durable state in `parent-state.py` / `parent-supervisor.py`. | **Consolidate only exact process primitives** (CI already reuses the smoke pidfd identity/stop implementation); retain separate supervisors and state transitions. Parent process tests remain in `tests/vm-parent-*.test.py`; CI primitives in `tests/ci-kvm-launch.test.py`. |
| SSH trust and command construction | Smoke acquires/pins its per-run host key and builds restricted SSH commands in `host-launcher.sh`; CI extracts the disposable guest key from serial and builds strict SSH options in `ci-kvm-contract.sh` / `ci-kvm-ssh.sh`; parent seals validated SSH identity through `parent-supervisor.py`. | **Intentionally separate.** Trust acquisition and key transport differ; only fixed option contracts may be shared if identical without weakening any path. |
| Readiness | Smoke classifies cloud-init and workload readiness in `host-launcher.sh` / `opencode-readiness.sh`; CI waits for cloud-init, strict SSH and test markers in `ci-kvm-capability.sh`; parent readiness is owned by `parent-supervisor.py`. | **Intentionally separate.** The readiness predicates describe distinct products and boot policies. |
| Persistence evidence | CI builders for fixture creation, flush and integrity verification are in `ci-kvm-contract.sh`, with reboot assertions in `ci-kvm-capability.sh`; the parent provides durable disk/state transitions in `parent-state.py` and `parent-supervisor.py`; smoke does not promise disk persistence across runs. | **Keep separate.** Reboot fixture proof is not parent durable-state management; smoke's transient lifecycle has no matching persistence contract. |
| Protected TUI, PTY and bounded capture | Smoke launches protected OpenCode through its fixed guest command; parent reuses `parent-session-contract.py`; hosted CI uses `ci-tui-capture.sh` and `ci-tui-diagnostic.py`. | **Consolidate explicit capture inputs only.** The capture helper now receives the SSH-TTY runner, diagnostic script, and failure reporter explicitly; parent and smoke launch policies stay distinct. Offline regression: `tests/ci-tui-capture.test.py`. |
| Restricted networking and egress | Smoke proxy and host/guest boundaries are in `host-launcher.sh`; CI changes QEMU to `restrict=on` and performs a bounded sampled probe; parent proxy policy is controlled by its gated supervisor. | **Intentionally separate.** CI's QEMU boundary and sampled probe do not establish the smoke proxy's or parent's network policy. |
| Callback-listener absence | The host smoke's port-file validation and `/proc/net/tcp{,6}` scan previously duplicated the browser-auth bridge's listener scan. Both now call `lib/vm/callback-listener.py`; bridge wrapper remains `browser-auth-session.py::listener_absent`. | **Consolidated.** Regression: `tests/vm-host-launcher.bats` exercises absent/present IPv4-mapped IPv6 listener handling; browser-auth and OAuth suites exercise proof-bearing cleanup. |
| Synthetic OAuth, stage deadlines and cleanup | CI OAuth simulator is `tests/ci-qemu-oauth-bridge.py`; bridge ownership/proof is `browser-auth-session.py`; smoke uses the same production bridge but its own outer stage budget and cleanup; CI deadline and QEMU cleanup remain in `ci-kvm-launch.sh` / `ci-kvm-capability.sh`. | **Share the actual bridge and process-identity primitives; keep orchestration separate.** The CI simulator is credential-free and guest-backed; smoke is owner-interactive. Do not add another supervisor. |
| Failure classification and diagnostics | Smoke sanitizes owner-facing status in `host-launcher.sh`; CI emits bounded stage/status evidence in `ci-kvm-capability.sh`; parent has durable lifecycle status in `parent-state.py`. | **Intentionally separate.** The reporting audiences and state machines differ; bounded logging utilities may be reused when their contracts match. |

These dispositions account for the identified boundaries without asserting that
all stages are already independently callable. B1's cross-Actions-step guest
ownership remains deferred to the separately reviewed shared-guest design.
